# Data Dictionary

Based on the actual raw CSV headers generated by `src/01_generate_data.py`. The cleaned fact files receive one derived `Term_ID` during ETL because the current source contains exactly one academic term and the raw marks/attendance records do not carry a term identifier. That derived field is not a raw source column.

## Keys and relationships
- Primary keys: Student_ID, Subject_ID, Marks_ID, Attendance_ID and Term_ID in their respective source tables.
- Foreign keys: marks.Student_ID → students.Student_ID; marks.Subject_ID → subjects.Subject_ID; attendance.Student_ID → students.Student_ID; attendance.Subject_ID → subjects.Subject_ID.
- Clean fact files add Term_ID and relate to academic_terms.Term_ID.
- Fact grain: one student × subject × term per marks row; one student × subject × term per attendance row.
- Raw CSVs intentionally include duplicate and invalid rows; uniqueness is expected after cleaning, not in raw files.

## Business-rule configuration
`config/business_rules.json` is the canonical configuration for the provisional attendance threshold, assessment component maxima, passing-mark default, grade bands and absent/missing labels. `src/07_export_business_rules.py` exports Power BI-friendly CSV copies. The subject-level Passing_Marks field is authoritative for each subject.

All numeric values are synthetic demonstration assumptions until institutional policy is supplied.
